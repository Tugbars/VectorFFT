# ZTURN-T above 2048: the investigation

**Owner direction (2026-09-09):** "investigate integrating zt-t to 2048+
first" — ahead of real 3D and rank 4. "If zt-t wins over zcascade, we ditch
zcascade and wire 2D and 3D on zt-t only." The scrambled contract and MT are
FEATURES the cascade serves today (`TODO_zcascade.md` item 6): if the cascade
goes, ZTURN-T gets a scrambled class and an MT arm as feature work. The
cascade's backward-terminator twin (`TODO_zcascade.md` item 1) is built only
if the cascade survives this verdict; the calibrator pacing (item 3) is
needed regardless — this verdict uses it.

**The law for every step (owner, 2026-09-09):** "the planner should race
different tiling options for each cell above 2048." Tiling is an AXIS, not a
rule: at every cell above 2048 each tiling option — the untiled driver and
every tile width the cell admits — is its own candidate in the natural pool,
the dp planner races them on its protocol, and the winner banks in the
cell's `il_ztt=` row (a tile field beside the chain), exactly as the
cascade's `tcut` axis is raced and banked today. No cell gets a tile width
by formula.

**The cell of comparison:** K=1 c2c interleaved, NATURAL order, T = 1, both
placements, N = 4096, 8192, 16384 first (the baked quarter-wave's octave);
32768 and above need the two-level create (`TODO_zcascade.md` item 2) and
come after. In this cell the cascade's only optimization advantage over
ZTURN-T is TILING (`zt_tw`, the 16 KB tile MKL's large path also runs);
ZTURN-T holds the smaller twiddle footprint and the spill-free backward.

## Step 1 — the untiled datum (in the tree, 2026-09-09)

ZTURN-T's ceiling was the driver cell list and the baked table, not the
kernels (size-blind) or the planner. Raised to 16384:

- `src/core/oop/ztt_qw16384.h` replaces `ztt_qw2048.h` (4097 doubles, 32 KB
  of .rodata; generated by `probes/ZT/zt_bake_qw.c 16384`). The 2048 table is
  contained in it bit for bit (index stride 8: the argument 2*pi*k/M is exact
  under a power-of-two rescale), so no stream below 2048 changed — the
  seeded replay in `ztt_gate` is the proof (bitwise the banked rows).
- `ztt.h`: `VFFT_ZTT_MAX_N 16384`, `VFFT_ZTT_QW_LGM 14`, shift `LGM - log2 RL`.
- `ztt_drivers.ml`: `max_n = 16384` — 82 cells (33 + 12 + 16 + 21), 328 fused
  drivers, regenerated by the promote rules (`generated/ztt_drivers_avx2.c`,
  `ztt_registry_avx2.h`).
- No planner change: `_il_dp_enumerate_ztt` already walks the registry at
  every N into the natural pool; the OOP natural door at N >= 2048 already
  races the K=1 winner against the natord cascade and banks `mode=free|zcasc`.
  The scrambled pool at N >= 2048 enumerates no natural engine, so
  `il_dp_overflow_gate`'s rows are unchanged.
- Gates: `ztt_gate` engine 82/82, seeded replay 11/11 (16..16384).

**Verdict protocol** (`probes/ZT/phaseE_2048plus.sh`): `calibrate_k1` on a
scratch copy of the store at 4096 8192 16384 (rigor 1) — the natural pool
(pairs x forms, chain3, ZTURN-T's 12/16/21 chains) and the scrambled pool
race and bank; `natoop_restamp` banks the door's verdict; then three arms
through the front door with the canonical bench in `--k1noop` mode, MKL in
the same process as the control: (a) the K=1 winner as banked, (b) ZTURN-T
pinned to its fastest chain (from the calibrator's `cand,` lines), (c) the
natord cascade (`mode=zcasc`). One fresh process per (cell, arm, run), arm
rotation, cooldowns, across-run spread beside the within-run one.

**What the datum decides.** At 4096 the plane (16N B = 64 KB) has just left
L1 (48 KB): untiled ZTURN-T vs the tiled cascade measures the tiling
advantage directly. At 8192 / 16384 (128 / 256 KB, L2-resident) it measures
the size of the gap a tiled ZTURN-T would have to close.

**Defect found by this verdict — the natural door's race buffers.** The door
(`c2c_oop_create.h`, `[natorder]`) raced both arms on plain `malloc` memory
(16-B aligned on Windows) while the planner (`VFFT_ZS_ALLOC`) and the bench
(posix_memalign 64) race on 64-B arenas. ZTURN-T's drivers store unaligned,
so an unaligned destination runs but splits lines: the door clocked ZTURN-T
at 3712 / 5904 / 3758 ns in three consecutive processes at 4096 and at
13550 ns at 8192 (bench: 8783), and banked the cascade at all three cells
against the paced verdict. Fixed 2026-09-09: the four door race sites
allocate 64-B aligned (owner's law: "always use aligned malloc"; the
tree-wide sweep is a separate gated step). After the fix, three processes:
4096 engine 3671 / 3871 / 3708 vs cascade 4017 / 4050 / 4008 (engine, all
three, as the bench); 16384 engine 18350 / 18770 / 18180 vs 18880 / 18820 /
18630 (engine, all three); 8192 a near-tie (8820 / 11320 / 8790 vs 8650 /
8860 / 8770, cascade by < 1% twice and one outlier) — the bench's +1.5% for
ZTURN-T there is inside the door's noise; the systematic bias is gone.

Gates after step 2 (2026-09-09): `ztt_gate` 82/82 with every legal tile

The tile pays at 8192 (untiled lost to MKL 0.97; tiled 1.05, +7.6% over

Two defects of mine caught by this verdict, both fixed the same day: the
K=1 IL row has TWO serializers in `wisdom2_oop_reader.h` (the replay print
and the bank path) and the tile reached only one, so the first pass banked

arm served ZTURN-T. Both are recorded in memory as traps.

**Step 2 verdict:** ZTURN-T, tiled where its race says so, wins the natural

decision on it: strip the cascade — `docs/design/zcascade_sunset_plan.md`.

## Step 2 — the tiled ZTURN-T (the tiling axis) — IN THE TREE 2026-09-09

Shipped as designed below with one refinement: the tile width is a RUNTIME
argument of every driver (`size_t tile`, 0 = untiled), not a corpus axis —
one driver per cell (82 cells, 328 drivers), the hot loops inside a group
literal, the tile loop and the per-tile group count runtime. The planner
enumerates untiled + each legal width of the ladder (`vfft_ztt_tile_legal`
the law: a power of two, >= the first mid's R*L, < N) as separate
candidates; the winner banks `il_tw=` beside `il_ztt=` and every replay
applies it (`vfft_ztt_set_tile`). Gate: every legal width bitwise the untiled
result (fwd, bwd, in place) on every cell, and a seeded `il_tw=1024` row
replayed through the front door.

**The ladder is 16 KB and 32 KB of plane** (1024 / 2048 complexes; owner's
ruling 2026-09-09 evening). The first ladder was the cascade's, 1 KB .. 64 KB;
the race over it at 2048..32768 (every chain x every width, planner clock,
`probes/ZT/phaseE2_calibrate.log`, `phaseE5_calibrate.log`) settled it:

- A width matters only through the stages it admits into L1: a stage runs in
  the tile iff its extent (the radix product through it) fits the tile; all
  other stages sweep the plane. Two widths that admit the same stages tie
  (8.8.8.8 at 4096: 16 KB 3556 ns, 32 KB 3565); a width that admits one more
  stage pays 5..8% (8.8.8.4.4 at 8192: 16 KB 8511, 32 KB 8007).
- 32 KB is the largest width that leaves L1 room for the twiddle streams
  (a 48 KB tile would fill the L1D; 64 KB never won a chain), so it admits
  the most stages and wins wherever it brings a stage in; 16 KB wins where
  it does not.
- No width below 16 KB ever admits a stage 16 KB leaves out. The 1..8 KB
  "wins" were ties on radix-4-heavy chains, which lose the cell anyway: at
  every cell the 8-first chains beat every 4-first chain by 8..15% (the
  ingest is the one untiled pass, and a radix-8 ingest does twice the work
  per gathered point there), and 6/7-stage chains sit 3..20% behind.
- Untiled stays the datum and wins 2048, whose 32 KB plane is L1-resident.

The cell winner is unchanged at 4096..16384 in both orders under the cut;
the calibration per ZTURN-T chain drops from up to 8 candidates to 3.
Widths of 3 * 2^k (12 / 24 / 48 KB) divide only planes with a factor of 3;
they belong to the 2^a * odd engine's ladder when it is built.

Runs are contiguous, so a tile of T complexes holds WHOLE groups of every
stage with RL <= T. The tiled driver is MKL's large path: per tile, the
load-permuted ingest (the probe's `t0tl` kind, emitted properly) writes the
tile contiguously from its strided columns, every stage with RL <= T runs on
the hot tile, then the cross-tile stages sweep the plane. Kernels unchanged.

The axis: per cell, one fused driver per (chain, tile width) the cell
admits — untiled, and every T from the smallest whole-group tile up to the
plane — each a registry entry, each a candidate; the race decides, the row
banks `il_ztt=<chain>` plus the tile. The corpus grows with the axis (the
cascade's `tcut` corpus is the precedent); gate as ZTURN-T was gated: tiled
== untiled bitwise, then the race.

## Step 3 — 32768 and above

The two-level twiddle create (baked coarse table x a per-N fine table, one
complex multiply per twiddle, ~1 ulp), registry cells to the cascade's
ceiling, the same tiling axis, the same protocol. MKL auto-threads 1D c2c at
N >= 8192 — the bench pins it to one thread already.

**IN THE TREE 2026-09-09 (evening).** `ztt.h`: ceiling 262144; above the
16384 octave `_ztt_fill_stage` splits pw = a*2^u + b (u = log2 RL - 14) and
takes table(a) x fine(b) with a per-stage fine table of 2^u <= 16 cos/sin
entries — the only trig the create runs. `ztt_drivers.ml max_n = 262144`:
223 cells, 892 drivers, the driver TU 2.5 MB. Gate: engine pass 223/223,
forward error ~1e-14 at 131072 (the two-level product's accuracy), every
tile bitwise. **Defect found by the seeded replay at 131072:** the
out-of-place commit condition in `c2c_oop_create.h` listed every K=1 IL
engine except ZTURN-T, so a ZTURN-T handle was committed only when the
SPLIT axis also had a route — true at every cell up to 65536 (masked), false
at 131072 where no split route exists: the replayed plan fell through to
"no interleaved engine". Fixed (`|| ztt`). Cold seeded 65536 served at 1.10x
MKL before any calibration. **Fused execution verified on this file**
(gcc -O2 -mavx2 -mfma, objdump): 892 driver functions, ZERO call
instructions inside any of them, no body left as a function; the 4096
8.8.8.8 dest driver is 1252 straight-line instructions, its plane twin 1279
with the 8 prefetches, the 262144 8^6 driver 2031. **Build cost:** the
2.5 MB TU compiles in ~90 s inside build.py's parallel build but took 17
minutes as a lone gcc -O2 compile on a loaded box; if it grows again, split
the TU per size or trim the chain enumeration above 65536 to what the
planner ever picks (a measured question). Calibration + paced verdict at
32768..262144: `probes/ZT/phaseE5_32k.sh`, running.

## Step 4 — if ZTURN-T wins the natural cell

Coverage before any sunset: the scrambled class (`t0ts`: runs stored in
column order, no `rb[]`, output digit-reversed) and an MT arm — feature
work, each its own gate and race. Then 2D and 3D on ZTURN-T. The cascade
retires per the pool sunset policy only when every contract it serves has a
ZTURN-T verdict.

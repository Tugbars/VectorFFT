# Consistency Report — 1D IL C2C vs 1D IL r2c/c2r (zr2c), SPLIT as maturity benchmark

## 1. Verdict

The zr2c composite is structurally sound and arithmetically correct — all eight (transform × placement × route) cells were traced in-buffer, input preservation holds on every OOP shape, normalization composes to the library-wide `bwd(fwd)=N·x`, allocation is leak-free on all seven build exits, recursion is bounded at depth 1 by the transform axis, and every axis it cannot serve (order, owned_buffers, config.batch, in-place at K>1, odd-N c2r) is refused loudly at create. The maturity ordering is **not** uniform in the direction the brief assumed: IL real is *ahead* of split on placement coverage (it is the library's only in-place real FFT) and ahead of both siblings on wisdom **lookup** discipline (it is the only IL reader that goes through `vw2_lookup` with full key equality; both kind-3 readers are hand-rolled scans that already silently erased a forward verdict once). What is genuinely behind is everything downstream of the create-time decision: the composite owns exactly **one** searchable bit, that bit has **never been measured anywhere** (37/37 shipped rows carry no `ns=`), the store shape it uses permanently shadows its own racer, no gate in the tree can catch a wrong or mis-keyed route verdict, and the canonical bench never builds a real plan through the front door at all — so nothing would notice. Against that, the highest-value maintainer work is not in the search space: it is four small contract holes where a *committed placement* is silently violated. **Fix order: D1 → D2 → D3 → D6 → D4/D5 → G1/G2.**

## 3. Confirmed gaps, ranked

**G1 — Nothing in the tree can catch a wrong, stale, or mis-keyed route verdict.** *(merges `no-gate-catches-wrong-route-verdict`, `no-kind5-store-roundtrip-gate`, `no-cold-replay-gate-for-real`)*
The route bit is the only thing kind-5 wisdom stores, and it has zero coverage in both directions. `vw2_oop_bank_zr2c_slot` / `vw2_oop_lookup_zr2c` are referenced **only** from `src/core/vfft.c:2317, 2360` and the migrator's verify leg (`wisdom2_migrate.h:611`) — no gate, no bench. `wisdom2_real_gate.h:122-157` stages a zr2c cell purely to prove *isolation*; it never banks or reads through the kind-5 codec. That codec is a 4-slot fan-in (`vfft_zr2c_kv_slot/_get/_set`, `wisdom2_oop.h:145`) reassembled from four independent per-slot records (`wisdom2_oop_reader.h:690-720`), so a mis-keyed slot (c2r/ip answering an r2c/oop query) serves the wrong route with no symptom. Both routes are correctness-gated, so the *only* observable consequence of a wrong verdict is speed — and G2 means speed is not measured either.
**Why it matters:** the one axis this engine owns is unverifiable end to end.
**Fix:** (a) a kind-5 leg in `wisdom2_real_gate.h`: bank all four slots at one N with distinct routes → save → reopen → assert the four `vfft_zr2c_kv_get` values, plus a cross-key negative; (b) a decode gate on the `sp_ccol_decode_gate.c` model — enumerate `eng=zr2c` records, resolve each through the production lookup, assert create built that route; (c) a cold/replay leg in `zr2c_fd_gate` (scratch dir): pass 1 asserts a race line per slot under `VFFT_ZRACE_VERBOSE`, pass 2 asserts no race and byte-identical output.

**G2 — The canonical bench never builds a real plan through the front door.** `bench_1d_vs_mkl.c:2502-2513` builds `cfg.transform = VFFT_C2C; cfg.n[0] = half;` and calls `_zr2c_fold_fwd`/`_bwd` directly (`:2586, :2602`). This is broader than zr2c: grep shows `VFFT_R2C`/`VFFT_C2R` appear in exactly three bench sources and **never** as a `cfg.transform` — `--r2c`/`--c2r` also build plan-level objects (`:2195, :2890-2924`). So no mode in the canonical bench exercises `vfft_create` for any real transform, the route-1 memcpy and route-0 scratch hop are never timed, and **the in-place shapes — the newest capability — have never been timed at all**. Directly violates the project's own front-door law (`zturn_tcut_gate.c:1-8`).
**Fix:** rewrite `run_zr2c_cell` to `vfft_create(R2C/C2R, INTERLEAVED, K=1)` for both placements, with `VFFT_ZR2C_ROUTE` forcing each arm so the table carries route 0 / route 1 / wisdom pick per cell.

**G3 — All 37 shipped kind-5 rows are bank-only `src=migrated`, which permanently shadows the racer.** Verified: 37 `eng=zr2c` rows, **0 with `ns=`**, 0 with `src=seed`. `vw2__is_seed` matches the literal `"seed"` only (`wisdom2.h:449-452`) and `"migrated"` ranks as `VW2_SRC_RACE` (`:442`), so `_zr2c_build` step 2 returns on every one of them (`vfft.c:2345-2366`) and the step-3 racer is unreachable at every keyed cell. The seeder exists and has never been run (`wisdom2_migrate.h:1329-1402`, driver `benches/wisdom2_migrate.c:41`).
**Honest scope** (per verification): 35 of 37 rows are byte-equal to `_zr2c_build`'s own structural fallback, so seeding them changes no behaviour until a race actually runs. Two rows *contradict* the fallback and currently govern live behaviour on an unverifiable claim: `t=c2r n=1024 place=oop route=child_nat_ip` and `t=c2r n=65536 place=oop route=child_nat_ip`.
**Fix:** run `wisdom2_migrate seed-zr2c` (it preserves the two out-of-pattern rows), race those two explicitly, and harden step 2 so a measure-less non-seed verdict cannot preempt the racer in measurement mode.

**G4 — `rigor` does not reach the child that does ~all the work.** The zr2c branch builds the child and returns (`vfft.c:5307-5311`); no search is launched. The split real branch does the opposite and says why — calibrate-on-miss for the inner c2c and the rfft axis at `cfg->rigor` (`vfft.c:5313-5330, 5335-5354`). Neither `vfft_il_dp_plan_and_bank` nor `vfft_sp_dp_plan_and_bank` has any caller under `src/`; on a kind-3 miss the child serves a balanced-pair heuristic forever (`vfft.c:4692-4760`). **This is PARITY with IL C2C and a GAP only against split** — the brief's "the real path is behind" framing does not hold here. Note the branch ordering is deliberate and documented (`vfft.c:5297-5306`).
**Fix:** add the child's N/2 cells to `calibrate_k1`'s default cell list. Do **not** call the IL DP planner inside `vfft_create` — that moves a full enumerate+gate+bench campaign into create, a different order of cost from split's `_calibrate_c2c`.
*Correction to a tempting cheap fix:* adding `vfft_il_dp_set_patient` to `calibrate_k1` would change nothing — `beam` only controls retention *after* every live candidate is benched (`dp_planner_il.h:1401-1403`), and `believe_cached_cost=0` only bites on a cache hit, which a one-plan-per-cell driver never produces. Depth requires a second `rank()` pass, as `calibrate_zchain` does.

**G5 — c2r's route and pair are picked on a forward metric.** `cost_ns` is the forward number for natural routes (`dp_planner_il.h:269-271`), the sort key is `cost_ns` (`:1391`), and the backward race runs only on `cand[0]` and only when it is 2P_PURE (`:1393-1394`). The c2r composite is backward-only (`vfft.c:2277-2287`), so only the kernel *forms* get a backward verdict. The planner's own comment defends the direction split for the kv axis on exactly this ground (`:275-283`, with a measured 2×16 mid at +23% backward / tie forward) and the argument was not carried up to the route and pair. Split's `_c2r_route_decide` (`vfft.c:1239-1300`) races on the backward metric and stamps `metric=bwd1`.
**Scope:** parity with IL C2C for a caller who only runs backward; the real-specific part is that a c2r handle is backward-only *by construction*, so the mis-ranking is unconditional.
**Fix:** cheap — extend `_il_dp_race_bwd` to the top-K rather than `cand[0]`. Honest — a `dir` axis on the cache key mirroring the `ord` treatment at `dp_planner_il.h:358-364`.

**G6 — The backward kernel-form pool is structurally narrower.** Backward blocked registries exist only at R∈{32,64}, variants 1–2 (`il2p.h:464-482`); the pool is walked blind over 1–4 by design (`dp_planner_il.h:954-970`) and an unresolved nibble is refused at build (`:452-453`). Forward carries variants 3/4 (tangent/turned) at R=32/16/8 (`:1105-1146`) — the constructions that won 128/256/512.
**Reachable half:** 6 backward tangent codelets (t2ttan/n1tan at R8, R16, and the R32 pair). Emit them and wire into `vfft_il2p_t2t_bwd_v_fn` / `_n1_bwd_v_fn`; the race picks them up with no planner edit. **Do not** ship a variant-4 backward twin (see U2).

**G7 — K==1 only; the fold is already batch-capable.** Gates at `vfft.c:5307, 5419`; `_zr2c_fold_fwd/_bwd` already take `size_t K, zs, xs` and document a transform-contiguous batch contract (`zr2c.h:52-55, 86-89, 164-167`), but every call site passes literal 1. K>1 IL real *is* served correctly in the documented lane-major layout (`vfft.h:351-353`), so this is a **performance + geometry** gap, not a capability hole. The tcb wrapper is the proven mechanism (`vfft.c:3174-3177`), and extending it to R2C/C2R also closes D10.
*Latent trap while it is inert:* all three forward fold sites pass `xs` for the `zs` argument; at `vfft.c:2264` the Z source is the scratch plane whose natural stride is N, not N+2. Harmless at K=1; a loaded gun for batched V9.

**G8 — The child config drops `recalibrate` and `wisdom_write`.** `_zr2c_build_route` memsets and hand-fills ten fields (`vfft.c:2199-2209`); neither control field is among them. Consequences after verification are **narrower than the audits claimed**:
- `recalibrate=1` re-decides only the route bit (`vfft.c:2348`). But a direct IL C2C create ignores `recalibrate` for the kind-3 lookup too (`vfft.c:4676-4679`, unguarded), so this is parity inside the IL family; what is genuinely lost is the child's `@nat`/`@natoop`/ZCASC re-race (`vfft.c:4074, 4509, 4996`), reachable only at child N ≥ 2048.
- **"the child's verdicts can never reach disk" is REFUTED.** The child is handed the parent's store (`c2.wisdom = cfg->wisdom`, `:2207`), child banks mark shards dirty, and `vw2_save` flushes **all** dirty shards (`wisdom2.h:1086-1096`) — so any later parent bank persists them. And `vfft_wisdom_save` (public, `vfft.c:7388-7409`) persists everything with no guard at all (see D7). The residue: when step 2 serves a banked route — i.e. all 37 shipped cells — the parent never banks, so child races stay memory-only and the "serving mode" warning fires misleadingly.
**Fix:** `vfft_config_t c2 = *cfg;` then override what differs, matching `vfft.c:3182-3185` and `4009-4010`. Then future config fields propagate by default instead of by remembering.

**G9 — No kill switch; the one env hook is undocumented and coarse.** `VFFT_ZR2C_ROUTE` is read above both the banked verdict and the race (`vfft.c:2336-2340`), so a process-wide environment variable silently outranks a caller-owned wisdom bundle the header says is used exclusively (`vfft.h:171-172`); it appears nowhere in `vfft.h`; the test is `atoi(e) != 0`, so `"true"` or `"oop"` silently selects route 0; there is no diagnostic; and it forces the same route on all four wisdom slots (`wisdom2_oop.h:151`) whereas split has one hook per transform (`vfft.c:1116, 1252`). There is no `VFFT_NO_ZR2C`, so the whole-route A/B (zr2c vs split-CCE at K=1) cannot be run through the front door.
**Fix:** add `VFFT_NO_ZR2C` at `vfft.c:2337` returning NULL; accept a per-slot spec; reject values outside {0,1}; document both in `vfft.h`.

**G10 — No refusal-matrix gate for real.** `vfft_tcbatch_gate.c:396-421` is the *only* expected-NULL assertion in the bench tree, and it covers C2C. Nothing asserts that in-place SPLIT real, in-place K>1, odd-N c2r, `order != DEFAULT`, `config.batch + IL`, or `owned_buffers + IL` are refused. Both D6 and D10 are exactly what such a gate exists to catch, and neither was caught.

**G11 — Prime-half and odd-half cells are ungated.** `zr2c_fd_gate.c:253` uses `{512, 2048, 4096}` — all powers of two — and the single non-pow2 cell is 510 (half 255 = 3·5·17, **not** prime) and is **r2c/OOP only** (`:207`). So the family of even N with a prime/Rader-class half — where route 0's OOP-IL child cannot be built (`vfft.c:5220-5237`), where the single-route fallback fires, and where D1 lives — has no test in either direction or placement. The gate's own header calls 510 "odd-N" and files it as a path the branch "must NOT disturb", when 510 is even and goes *through* zr2c: a comment that outlived its code, inside the gate held up as the correctness benchmark.

**G12 — The route race is not pinned to single thread.** `_r2c_route_decide` and `_c2r_route_decide` snapshot, force 1, race, restore (`vfft.c:1147-1155, 1283-1291`) precisely so the banked verdict is an ST verdict; `_zr2c_build` (`:2373-2445`) does none of this, while `c2.nthreads = cfg->nthreads` (`:2208`) and the kind-5 key carries no thread axis (`wisdom2_oop_reader.h:665-668`). Latent today (K==1 never reaches an MT arm at `vfft.c:6096-6103`), but it invalidates the numbers the G3 re-race is about to bank, and this project has already manufactured one fake MT verdict from pool-parking. **Fix before re-racing, not after.**

**G13 — Verdict auditability.** `_bank_zr2c` has both arm medians in hand (`vfft.c:2428`) and passes one (`:2438`); the writer takes one `ns` and emits no `arms=` (`wisdom2_oop_reader.h:658-683`). Split emits `arms=win/lose` "so the line reads back as the race it was" (`wisdom2_real_reader.h:176-188`). For a 3%-hysteresis one-bit decision the margin *is* the content. Separately, the record cites nothing: the child recipe that carries ~all the cost lives in `(t=c2c, n=N/2, q=1, ord=nat, place=oop|ip, role=comp)` and there is no `ref=` to it, so a banked route verdict is not deterministically replayable end to end. (Emit `ref=` **conditionally** — only when the target exists — or the dangling-ref law turns every zr2c verdict into a permanent miss.)
*Settle D13 first* or the new writer inherits the wrong `arms=` representation.

**G14 — Single-threaded, advertised as MT.** `_exec_zr2c` uses no pool, both folds are serial loops (`zr2c.h:92, 170`), the K==1 child cannot reach the IL MT arm (`vfft.c:6096-6103`), and `grep -n 'thread|pool|_mt(' src/core/oop/zturn.h zsplit.h` returns nothing — so even the ZCASC child is serial. `vfft.h:24-25` advertises "MT yes" for R2C/C2R with no layout caveat. This is **PARITY** on capability (split is also serial at K=1) plus a documentation gap.

**G15 — The benchmark engine's own holes** (recorded so the maturity comparison is not read one-directionally): `dp_planner_split_oop` caps at 128 candidates / 32 plans and enforces them with bare `continue`/`break` — no counter, no message, no refusal (`:126-127, 421-482`), whereas IL counts drops and refuses the cell because "a truncated pool is a BIASED pool" (`dp_planner_il.h:1018-1027, 1303-1318`). Not binding for shipped pow2 cells; live for the chartered odd/prime extension (`:57-61`). And split's classic pairs have **no kernel-form axis** at all (`:119-124, 420`) — the already-banked "missing sp_kv axis".

**G16 — The IL C2C wisdom readers are the undisciplined side** (latent, but the direction is worth recording). `vw2_oop_lookup_k1` is a hand-rolled scan matching on `(t, rank, n[0], eng)` only (`wisdom2_oop_reader.h:112-131`); it needed an emergency `key.dir != VW2_DIR_NONE` patch after the new bwd sibling started matching there and **silently erasing the forward verdict** (`:129`, with its own 🔴 comment). `vw2_oop_lookup_k1_bwd` (`:186-201`) has no q/ord/place/role check and no wildcard pass. Because they bypass `vw2_lookup`, they also bypass `vw2__ref_ok` — verified: its only two call sites are `wisdom2.h:955, 966`, both inside `vw2_lookup` — so a kind-3 record whose `ref=` cascade target has been deleted or re-keyed is served anyway, in violation of the dangling-ref law. kind-3 *does* emit `ref=` (`wisdom2_oop_reader.h:441-444`, IL route CASCADE). Latent only because no shipped kind-3 row currently carries `ref=`.
**Fix:** reroute both through `vw2_lookup` with the concrete canonical key, keeping a wildcard fallback for the migrated vintage.

**G17 — Pair-ordering memo has no eviction.** `_ord_n[8]` / `_ord_pick[8]` (`vfft.c:2584-2591`); on overflow `ord_slot` stays −1 and the pick is never recorded, so the race re-runs per create and the bitwise-identity guarantee between sibling handles that the memo exists for is silently lost (`:2571-2583`). Narrower than first stated: only *uncalibrated* sub-2048 in-place-natural cells consume slots, so >8 such cells in one process are needed.

## 4. Defects (actual bugs) — most actionable output

**D1 — In-place real create silently degrades to an out-of-place split plan.** *(merged from `architecture/inplace-fallthrough-to-split`, `execute/missed`, `features/zr2c-fallthrough-noise-at-n2`, `api_gates/silent-fallthrough-keeps-inplace-label`)*
Both real branches are `if (hz) return hz;` with **no placement re-check** (`vfft.c:5307-5311`, `5419-5424`). The in-place gate at `vfft.c:3275-3290` has already *admitted* this shape, so the split branch stamps `h->placement = cfg->placement` (`:5373`, `:5457`) onto a handle whose executor is the OOP CCE path (`vfft_r2c_execute_fwd_z` at `:6855`, `vfft_c2r_disp_execute_z` at `:6869`), engines that stream an N-double real plane into an N+2-double CCE plane and were never gated for aliasing. The caller then makes the documented `(z,NULL,z,NULL)` call and gets an OOP executor whose source aliases its destination.
**Reachability (corrected):** *not* via prime halves on the default path — `vfft.c:2373-2375` builds both arms and returns the survivor. It is reachable via (a) a **banked verdict naming the unbuildable route**, which returns `_zr2c_build_route` directly with no fallback (`vfft.c:2364-2365`) — and every shipped cell is banked, two of them out-of-pattern; (b) `VFFT_ZR2C_ROUTE` forcing that route; (c) both children failing; (d) aff/scratch malloc failure (`:2216-2227`). The sanctioning comment at `vfft.c:5300-5306` predates the in-place capability.
**Fix:** after the fall-through, `if (cfg->placement == VFFT_INPLACE) { warn; return NULL; }` at both sites.

**D2 — The public header declares in-place real REFUSED while it ships.** `vfft.h:24-25` ("R2C/C2R … OOP (IP: refused for now)"), `vfft.h:377-379` ("in-place real FFT is REJECTED loudly until an MKL-style in-place CCE path exists"), and the signature table (`vfft.h:339-360`) has no in-place real row — against `vfft.c:3275-3290` + `_exec_zr2c`, shipped since §D2. Consequences: the library's only in-place real FFT is undiscoverable; the **only** statement of the required `2*(N/2+1)`-double plane size lives inside the refusal string for the *other* shapes; there is no public sizing helper (`vfft_plan_planes`/`vfft_plan_stride` are owned_buffers/SPLIT-only, and `_own_batch_for` refuses INTERLEAVED outright at `vfft.c:7212-7218`). Also undocumented: in-place real accepts **only** the fully-aliased spelling — `dre==NULL` is refused (`vfft.c:6371-6377, 6412-6418`) where in-place IL C2C normalizes it (`:6705, 6712`).
**Fix:** correct both header sites, add the in-place rows to the signature table with the padded-plane contract, and export `vfft_cce_doubles(N)`.

**D3 — Route-1 in-place R2C never reads `sre`; the real arms of `_vfft_sig_bad` enforce no placement and no aliasing.** `vfft.c:2269-2272`: the memcpy is gated on `h->placement == VFFT_OUTOFPLACE`, then the child runs on `dre` — so an in-place plan called with `dre != sre` transforms whatever is in `dre`. Route 0 reads `sre` and is correct under the identical misuse (`:2261-2265`). **Measured: relerr 9.8e-15 on route 0, relerr 1.000 on route 1, no warning either way.** `_vfft_sig_bad`'s R2C block (`:6358-6398`) and C2R block (`:6399-6437`) never read `h->placement` and never test `dre==sre`.
**Scoping (from verification):** `dre != sre` on an in-place plan is undocumented misuse, and the IL C2C arm has no placement check either (`:6441-6457`) — it merely survives it because its engines take `(z_in, z_out)` pairs. c2r is safe on both routes. So this is not "real lost a check C2C has"; it is that **the two routes of one plan diverge under identical misuse, and which behaviour you get is a measured wisdom verdict.** That is the disqualifying property.
**Fix:** make route 1's memcpy `if (dre != sre)` (one line, makes the routes semantically identical), **and** add the placement/alias rules to the real arms of `_vfft_sig_bad`, matching `vfft.c:6484-6512`. Note the OOP-aliased case is currently *correct* on both routes and on c2r — refuse it deliberately or document it, but do not "fix" c2r into a refusal of working behaviour.

**D4 — The kind-5 banker stamps `metric="fwd1"` on the c2r slots.** `wisdom2_oop_reader.h:677`, unconditional, though `is_c2r` is in hand at `:666`; the c2r race times a backward composite (`vfft.c:2275-2287, 2413-2428`). **D5 — No reciprocal engine-ownership guard on the zr2c cell.** `vw2_oop_bank_zr2c_slot` (`wisdom2_oop_reader.h:658-683`) writes `{t=r2c|c2r, rank=1, n=N, q=1, ord=nat, place}` — **byte-identical** to the split route key at K=1 (`wisdom2_real_reader.h:160-163`) — and `vw2__bank_pinned` upserts on key equality alone with `eng` a mere payload token (`wisdom2.h:988-1007`). Interim: add the reciprocal `cell_taken` guard and a loud line on foreign-eng read; extend `wisdom2_real_gate.h` check 3 to the symmetric direction.

**D6 — The in-place real gate tests `cfg->dims == 1`, refusing the documented `dims == 0` spelling of 1D.** `vfft.c:3282`, against `vfft.c:3096-3099` ("0 is accepted as 1D"), `:3103` (`nd = cfg->dims < 1 ? 1 : cfg->dims`), and `dims < 2` at `:3176, :3298`. **D7 — `vfft_wisdom_save` persists with no `wisdom_write` guard.** `vfft.c:7388-7409` marks **every** non-poisoned shard dirty and calls `vw2_save` unconditionally; `config.wisdom_write` is not in scope. **D9 — `_bank_zr2c` discards the banker's return and persists anyway.** `vfft.c:2314-2318`. `vw2_oop_bank_zr2c_slot` can return −1 or `VW2_E*` (`EMETRIC`, `ERANK`, `EWILDCARD`, `EPOISON`, `EREADONLY`). ## 5. UNREACHABLE by construction — do not reopen

**U1 — The scrambled half of the IL C2C search space.** The child is created `order = VFFT_ORDER_NATURAL` unconditionally (`vfft.c:2206`) and every kind-5 key is `ord=nat` (`wisdom2_oop_reader.h:667`). **Structural reason:** the Hermitian fold pairs each bin `f` with its mirror `half−f` (`zr2c.h:31-34`), so a digit-scrambled spectrum breaks the fold's index arithmetic outright. Two clarifications so this is not later reopened from the wrong side: (a) the `order` axis is refused at the **front door** for every non-C2C transform (`vfft.c:3130-3143`), so `c2.order` cannot contradict a user request — this is a contract, not a pass-through defect, and "fixing" the child config into a struct copy must not propagate an order the front door already rejected; (b) the split real `ord=scr place=ip` rows are **not** evidence of a scrambled real capability — `vw2_stride_rec_from_entry_t` hardcodes `VW2_ORD_SCR, VW2_PL_IP` into the key for every stride/rfft record (`wisdom2_stride_reader.h:321`). Parity with IL C2C for the interleaved real path means parity with its natural half only.

**U2 — A variant-4 (turned-axis / `VFFT_CX_STORE128`) backward twin.** The mechanism is forward-only by construction and a probe produced a byte-identical backward file to variant 3. Shipping one would recreate the two-codes-one-plan hazard. *Caveat: this rests on `docs/search_space/parity_plan.md:100-107`, written by this same campaign — re-ground it on the probe output before acting.* The other direction of the asymmetry is also structural: backward has blocked R=64, forward has none.

**U3 — An MT gate for IL real.** `_exec_zr2c` uses no pool and the K==1 child cannot reach the IL MT arm (`vfft.c:6096-6103`, `T <= 1 || K < 8`). There is no threaded code path to gate. Recorded so the absence is not mistaken for an untested threaded path — which `vfft.h:24-25` currently makes it look like (see G14).

**U4 — The `if (!W)` branch in `_zr2c_build`** (`vfft.c:2367-2371`), and the `W &&` guard at `:2348`. `_default_wisdom` returns a file-static that is never NULL (`vfft.c:502-512`) and both call sites pass the resolved `W`. Dead code — but it makes the real law explicit: **there is no no-wisdom escape, so every kind-5-missing cell races**.

**U5 — In-place split real.** The split spectrum and real data are separate planes, so an in-place contract would be a lie (`vfft.c:3277-3279`). Not a gap in split.

**U6 — Kernel-form work above real N = 8192.** The IL pair space needs `R1*R2 = N` with both radices in the il2p registries, which stop at R=64, so 2-pass IL tops out at N=4096 and the child is `c2c(N/2)`. Real 8192 → child 4096 → exactly one legal pair (64×64); real ≥16384 → **zero** IL pair arms. *Count corrected:* the 37 rows are 4 each at 256/512/1024/2048/4096/8192/16384/32768/65536 plus 1 at 510, so **13** rows (the twelve at 16384–65536 plus 510, whose half 255 is odd) sit outside the kernel-form-reachable band — not 21. Prioritisation consequence stands: above real 8192 the route bit is the only thing that can matter.

**U7 — A fold variant axis.** One fixed implementation, fixed strides, no registry, no env hook (`zr2c.h`, `vfft.c:2256-2284`). An axis over a set of size one is not an axis; making it one requires writing alternatives first (an L1-blocked fold, or one fused into the child's terminator).

## 6. DIVERGENT by design — justified

**V1 — The race builds two complete composites and times them through `_exec_zr2c`.** `vfft.c:2373-2374, 2398-2427`. Justified: the thing being raced *is* the composite (memcpy/scratch hops included), and only a finished handle can run through `_exec_zr2c`. Atomicity holds — the loser dies before the handle escapes (`:2438-2444`), and its child is reclaimed by the recursive destroy (`:6963`). Cost is architectural and worth stating: peak create memory ~2×, and each arm may run its own create-time races inside the timed window.

**V2 — The child is created through the public `vfft_create`.** `vfft.c:2210`. Correct choice — it re-runs every front-door gate and inherits every K=1 IL route, wisdom verdict and race for free, which is the strongest structural argument for the zr2c shape (odd/prime coverage comes at zero cost). Price: a second `_vfft_sig_bad` pass and a second `vfft_set_num_threads` per shot, and child diagnostics reaching an r2c caller (see D15).

**V3 — The route race ignores `rigor`.** `_zr2c_build` never reads it (`vfft.c:2334-2446`); the doctrine is stated at `:2367-2369` ("the library is measured-only — there is no ESTIMATE tier"). Split windows its races instead (`vfft.c:5362, 5446`). Defensible, with two consequences to record: VFFT_MEASURE pays ~10 ms plus two full child creates per unmeasured slot, and PATIENT/EXHAUSTIVE buy no extra *route* depth. *Correction:* rigor is **not** inert on this engine — it is passed through at `vfft.c:2201` and governs whatever calibrate-on-miss the child's own create reaches. Only the one-bit axis has nothing to widen. Pick a policy deliberately; today it is neither windowed nor scaled.

**V4 — The two race arms are different engines and different child cells.** Route 0's child is an OOP-IL `c2c(N/2)`, route 1's is in-place natural (`vfft.c:2201`) — a designed route difference, not a methodology error. But the banked bit does conflate route structure with child calibration state, because route 1's in-place child gets a create-time pair-ordering race (`vfft.c:2596-2655`) that the OOP block explicitly lacks ("it has no race home — availability-attach", `:2574-2578`). *Not live on any shipped cell:* the race is gated on `!(ke && ke->il_R1)` and every zr2c child N has a kind-3 line with `il_pair` (`wisdom2_oop.txt:49-96`); the sole exception is real 510 (child 255, odd, no legal IL pair). If the confound is ever closed, note that the zr2c route race **is** the OOP block's missing race home.

**V5 — In-place race arms are never reseeded.** `vfft.c:2388-2395` seeds once; for the two in-place slots `s0 == dst == b` (`:2396`), so across 9 rounds × up to 64 reps each pass consumes its predecessor's output and magnitudes reach inf/NaN within a few dozen reps. Deliberate and documented ("junk-reps for the in-place shapes (natarm precedent)", `:2329`), and inf/NaN carry no denormal penalty on AVX2 — but it contradicts the reseed rule stated 200 lines below (`:2617-2621`, "repeated in-place fwd amplifies magnitudes toward inf — the ZCASC-race hazard"), and the OOP arms are immune, so the two placements are not measured under the same regime. One `memcpy` per burst would close it.

**V6 — Warm-up asymmetry.** Split racers run 5 warm-ups of **both** arms before timing (`vfft.c:1068-1077`); zr2c uses one un-warmed shot per arm as both warm-up and rep estimator (`:2399-2409`), with route 0 first — so route 0 absorbs first-touch faults on `b`. It does not bias the verdict (est feeds only `reps = 3.0e5/est`, clamped [2,64]) but it derives the rep count from a cold measurement, which can land at the floor of 2 for large N and produce bursts far shorter than the ~300 µs the protocol comment claims.

**V7 — The K>1 split real route race times a different terminator than the IL consumer runs.** `_r2c_build_arm` hardcodes `VFFT_R2C_SPLIT` (`vfft.c:1040-1041`) and the race times `vfft_r2c_execute_fwd` (`:1084, 1088`), while an IL caller runs `vfft_r2c_execute_fwd_z` → `rfft_execute_fwd_natural(..., z)` (`r2c_dispatch.h:480-489`), the native interleaved stage-0 terminator. Deliberate: layout is never a key token, it is a strategy output. Recorded as the one place an IL real cell's verdict is measured on something other than what runs — the first thing to re-check if a K>1 IL real cell ever measures off.

**V8 — Eager scratch allocation with create-time failure** (`vfft.c:2217-2228`) versus IL C2C's lazy first-execute allocation with a silent no-op on OOM (`:6034-6053`). zr2c's is strictly the more robust of the two. (Hygiene nit, not a gap: both zr2c allocations are plain `malloc` while every other SIMD-visible plane in the family is 64B-aligned; the folds are `loadu`-only so it is a discipline/perf item, and route-0 R2C+OOP carries an `(N+2)*8` block it never touches.)

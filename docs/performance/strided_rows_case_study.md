# The row-pass transpose tax: a measured case study

*docs/performance/strided_rows_case_study.md — 2026-07-14. How a "why are we losing
at 64³" question decomposed into host physics, a 19.7% structural tax, and a cure
that had been sitting in the codelet tree all along. All numbers: shared cloud Xeon
(AVX-512, 1 vCPU, ~3× session throughput swings — same-process ratios only), MKL CCE
interleaved, exhaustive plans unless noted.*

---

## 1. Problem definition

At matched AVX-512, same-process, best plans, the 3D column read:

```
 32³   0.768×      64³   0.958×      128³   1.171×
```

Monotone in size, crossing to wins only DRAM-ward of ~64³. The question, precisely
posed: is the planner failing to use the codelet inventory, are we paying a layout
tax, or is something else the cap?

## 2. Diagnosis (everything measured, nothing assumed)

**Host physics first.** A 12-chain dense-FMA probe put this host's 512-bit width gain
at **1.26×** (0.48 vec/cyc @256b → 0.31 @512b; absolute throughput ~¼ of a dedicated
core — license downclock + SMT tenancy). Any FMA-bound code caps there; MKL's apparent
2.5–3× "AVX-512 gain" is therefore a kernel-family swap (weak AVX2 multi-dim path vs
flagship 512 path), not width.

**Planner exonerated.** Exhaustive search at 64³ chose `[16×4]` / `[2×32]` / `[8×8]`
DIT — racing and *rejecting* both DIF and the mono `r64` at these (N,K). Plan quality
was worth 6–25% over the container-degraded DP (16⁴ flipped 0.93→1.16× on planning
alone), but chains were never the structural story.

**The per-pass anatomy** (64³, isolated timing of each phase):

```
 pass A axis0 (K=4096)      1,577,919 cyc   32.3%
 pass B axis1 ×64 (K=64)    1,123,844 cyc   23.0%
 row pass total             2,190,301 cyc   44.8%
   rows FFT only              868,143
   rows TRANSPOSES            928,599   ← the finding
 whole plan                 4,715,959   |  MKL 4,701,056  (0.997× that run)
 naive 5N·lgN FMA floor     ~4,810,000
```

**The diagnosis in one line:** both libraries sit pinned near the host's compute wall,
and the single structural difference is that our tiled row pass spends **19.7% of the
entire transform moving data through L1 scratch** — the gather/scatter transposes cost
more than the row FFTs they serve. MKL's fused small-3D kernels do that movement in
registers. Counterfactual (transposes free): 4.72M → 3.79M → a 1.24× win.

## 3. Solution

The cure predated the diagnosis: the **strided codelet quadrant**
(`codelets/strided/`, provenance: "Family: strided-batch (Design C, 2D rows)") — mono
`n1` codelets that load VW *consecutive rows in their natural contiguous layout*
(`rio[(b+0..b+VW-1)·row_stride + col]`), transpose **in registers** (the 4×4/8×8
unpack lattice), run the full N-point FFT, and store back transposed. No scratch, no
separate transpose pass, no gathers. Coverage: N ∈ {4,8,12,16,20,32,64} at AVX2,
{8,16,32,64} at AVX-512; regenerated by gen_set, so the constant fix flows through.

**Isolated race** (64³ rows, R=4096, both paths on identical data):

```
                      AVX-512            AVX2
 transpose+native     2,165,620 cyc      2,204,168 cyc
 STRIDED (best me)    1,258,684          1,573,320
 speedup              1.72×              1.40×
```

Gates before any wiring: strided fwd→bwd roundtrip ≤ 1.3e-13; per-row sorted-|X|
multiset vs the native path exact (0.0 at 512) — the strided pair emits a *different
but equally valid* scramble, so fwd and bwd swap together and the roundtrip contract
holds.

**Wiring** (`strided_rows.h`, shared by fft3d.h and fftnd.h; opt-in
`-DVFFT_STRIDED_ROWS`): per-ISA dispatch table resolved at plan build; the tiled
range runs the VW-aligned bulk through one strided call and drops sub-VW tails to the
native tile path (fwd/bwd tails cover the same rows → contract holds row-wise);
uncovered N_last and the natural-order tape path stay native automatically; MT
partitions land on B ≥ VW multiples, so per-row results are T-invariant. Correctness
after wiring: fft3d 49/49 and the full fftnd matrix (fused windows, primes, MT
bit-EXACT across T∈{1,2,4,8}) ALL PASS with the flag on *and* off.

## 4. Results

Whole-transform, matched AVX-512, exhaustive plans, same-process vs MKL CCE:

```
 cell        pre-strided     STRIDED        note
 ─────────────────────────────────────────────────────────────────────
 32³           0.768×        1.171×  WIN    (1.095× in a later window)
 64³           0.958×        1.141×  WIN    vfft 4.80M → 3.98M cyc
 16⁴           1.159×        1.487×  WIN    vfft 1.06M → 0.78M (−26%)
 32³×64 s=1    1.050×        ~unchanged     see nuance below
 128³          1.171×        (not re-run)   flat path → expected gain
```

**The nuance that matters:** at 32³×64 the fused s=1 cycles did not move (41.3M →
42.0M; the 1.512× printed that window reflects an MKL tenancy dip, not strided gain).
Inside a fused block the tile scratch is already cache-resident — **fusion had
already amortized most of the transpose tax there**. Strided rows and fusion are
complementary attacks on the same cost: strided wins where the tiled pass runs
flat/large (fft3d, s = rank−1, small-block cells like 16⁴); fusion wins by making the
tax cheap wherever it applies. Which combination wins is a per-(cell, s, ISA)
question — i.e. **a calibrator/wisdom axis**, which is the intended end state of the
`VFFT_STRIDED_ROWS` flag.

**Order semantics upgrade (same day, user-caught):** a single-radix mono is a
one-digit chain — digit reversal is identity — so **the strided output is NATURAL
order along its axis**. Probed and confirmed ≤1.1e-15 across r8/16/32/64 on both
ISAs. This inverts the natural-mode wiring: strided is not excluded from
ORDER_NATURAL, it *is* the tape-free natural path for the covered bulk (sub-VW tails
run native+cycle-tape, also natural → consistent output). The API now encodes it:
`_vfft_strided_verify_natural()` re-proves the property at plan time
(probe-don't-assume; any failure NULLs the pair → native+tape fail-safe), all three
resolves accept natural mode, and `fftnd_natorder_maps` returns the last-axis
identity WITHOUT a probe transform when strided is active — contract, not
assumption. Gates: full-plan row-axis-natural check (impulse at (0,…,1) → every
output row must be the natural phase ramp) passes on every strided-covered 2D cell;
the natorder per-bin external suite passes through the fast path.

**2D wiring** (same day): fft2d shares `strided_rows.h` — resolve guarded against
Bailey mode (`plan_row->K == N1`) and the natural-order tape (fft2d's natorder cycle
passes live inside the tiled loop, so strided must not bypass them). Correctness 5/5:
strided cells (N2 ∈ {16,32,64}) and fallback cells (20, 61) cross-checked against the
*independent* fftnd rank-2 path (sorted-|X| ≤ 1.9e-16), roundtrips ~1e-15.
Whole-transform at 4096×64 (auto inners, interleaved rounds): 2.98M → 2.62M cyc,
**1.14×** — smaller than 3D because the N1=4096 column pass dominates the 2D share.
Coverage honesty: strided monos top out at N=64, so classic long-row 2D (N2 =
256–4096) is untouched until strided *twiddle-stage* codelets exist — that emission is
the quadrant's real growth direction.

**Tail handling (same day, user-caught before it bit):** the coverage map marks
strided as the HARD family — no remainder loop, and my original fall-through sent
sub-VW tail rows to the native chain, producing MIXED per-row order (bulk natural,
tail scrambled) that silently invalidated the natorder identity fast-path whenever
R % VW ≠ 0. Fixed per the map's option (a), realized at the orchestrator:
`_vfft_strided_tail_padded` stages the rem rows into a zero-padded VW slab inside the
existing tile scratch, runs one me=VW strided call, copies back — uniform natural
order for ANY R, with a B ≥ VW resolve guard sizing the staging. Proven by the
adversarial matrix (`test_fftnd_tails.c`, both ISAs): odd-K cells (7×5×9, 9×7×15,
3×7×5×9 — K odd through every pass, the avx512 masked in-place tails' first multi-dim
workout) and strided-tail cells (rem ∈ {1,3,5,7} at r8/16/32/64), all gated per-bin
against a long-double reference THROUGH the identity fast-path at 2.2–3.2 eps, MT
bit-exact. The friendly-shape blind spot is closed on both the native and strided
paths.

## 5. Remaining

`fftnd_r2c` row pass takes the same wiring (its r2c rows are a different worker — the
strided quadrant is c2c-mono, so that one needs either strided r2c emission or stays
transpose-based). The 14900KF race decides the AVX2 production default (isolated 1.40×
says it should win on flat paths there too — but that is exactly the sentence this
codebase does not publish without the measurement). Calibrator integration: `rows=`
joins `s`/`blk`/`T` in the wisdom key. And the strided quadrant's coverage map
(`arbitrary_k_codelet_coverage_map.md`) already flags the arbitrary-me story as HARD —
sub-VW tails stay on the native path by design.

*The moral, for the arXiv narrative: the losses were never in the butterflies. One
measured decomposition located a 19.7% data-movement tax; the fix was zero new
mathematics — a forgotten codelet family, four correctness gates, and a flag.*
